# HiveMind v3 integration

`thalovant/noise.h` implements the actual Noise state machine and binary wire
cipher. It is transport independent: your application supplies WSS, HTTP or
MQTT connections, timers, serialized send order and bounded receive storage.
The core contains no heap allocation, socket calls or external dependencies.

## Identity and cryptography

Persist a 32-byte X25519 private key per client identity in protected storage.
Generate it with the platform CSPRNG once. Generate a fresh 32-byte ephemeral
private key for **every** connection, including reconnects. Store the hub's
32-byte static public key after an authenticated handshake and bind it to the
hub `node_id`. A known pin is enforced in both XX and KK; do not delete a pin
or retry with weaker authentication on a failed handshake.

The PSK is exactly Argon2id v1.3(password UTF-8, SHA256(node_id UTF-8)), with
3 passes, 65536 KiB, 1 lane and 32-byte output. `thalovant_noise_psk` derives it
using `THALOVANT_NOISE_PSK_MEMORY_WORDS` caller-provided `uint64_t` words and
wipes the 64 MiB scratch afterward. A constrained device can receive that
exact PSK through secure provisioning instead. Bind any cached PSK to the
password revision and hub node id; a cheaper KDF or the legacy `crypto_key`
is not compatible. Static keys, PSKs and entropy are never generated by core.

The in-tree AES256 path uses an algebraic S-box without secret-indexed table
lookups, X25519 uses a fixed Montgomery ladder, and authentication tags and
pins use constant-time comparison. Argon2id has the data-dependent indexing
specified by its standard. These are first-party implementations checked
against independent implementations and public vectors; no third-party code
is vendored. Platform threat models may still require specialist review.

## Handshake and canonical prologue

1. Preserve the complete initial `hello.payload` containing `node_id`, then the
   complete `shake.payload` parameter offer. Do not remove unknown fields.
2. Pass the advertised Noise pattern and suite lists to
   `thalovant_noise_select`. It chooses pinned `KKpsk0` when offered, otherwise
   `XXpsk2`. Only `25519_AESGCM_SHA256` is implemented. Missing `noise`, legacy
   offers, and offers with no common suite/pattern must close the connection.
3. Canonicalize both JSON payload objects with recursively sorted Unicode
   keys, compact separators, literal UTF-8 and unescaped `/`, matching Python
   `json.dumps(sort_keys=True,separators=(',',':'),ensure_ascii=False)`.
   Negotiation fields are strings, integers, booleans, arrays and objects;
   reject unsupported numeric forms rather than silently rewriting them.
   Concatenate canonical HELLO + canonical offer + the selected full protocol
   name, without separators. The names are
   `Noise_XXpsk2_25519_AESGCM_SHA256` and
   `Noise_KKpsk0_25519_AESGCM_SHA256`.
4. Call `thalovant_noise_init(..., initiator=1, ...)` with that prologue,
   persistent private key, fresh ephemeral, PSK and any known pin. The initial
   `thalovant_noise_write` payload is exactly
   `{"binarize":false,"encodings":[]}`. Wrap its output as hex in:

   ```json
   {"msg_type":"shake","payload":{"noise":{"pattern":"XXpsk2","suite":"25519_AESGCM_SHA256","msg":"<hex>"}},"metadata":{},"route":[]}
   ```

5. Decode the hub continuation `payload.noise.msg` strictly as hex and pass it
   to `thalovant_noise_read`. For XX, call `thalovant_noise_write` again with an
   empty payload and send a final envelope containing only `noise.msg`. KK
   completes after the hub response. Persist `state.remote_static` only after
   authentication succeeds. Finish sending handshake frames before application
   data; `state.ready` is a crypto state, not proof that your socket sent bytes.
6. The first encrypted application frame is the ordinary HiveMind `hello`
   containing `site_id`, `pubkey` and `session.session_id`. Send it as described
   below. Only then report the connection ready to callers.

Allocate at least payload length + 96 bytes for each handshake write and at
least received-message length for each read output. Every error is terminal,
including an insufficient buffer: close the connection and call
`thalovant_noise_init` with a **new ephemeral key** for the next attempt.
No connection function silently downgrades or erases a pin.

## Application frames

Use existing frame/ask/intent builders for application JSON. Prefix a single
JSON message with byte `0x00`, then call `thalovant_noise_encrypt`. The result
is ciphertext plus its 16-byte GCM tag, with **no legacy nonce prefix**:

```c
/* noise is a successfully handshaken thalovant_noise, not a raw crypto key.
 * Caller serializes this operation with every other send on this connection. */
uint8_t plaintext[1025], ciphertext[1041];
size_t json_len = strlen(json_frame), sealed_len = 0;
if (json_len > sizeof(plaintext) - 1) { /* reject oversized input */ }
else {
    plaintext[0] = 0; /* FRAME_JSON */
    memcpy(plaintext + 1, json_frame, json_len);
    int rc = thalovant_noise_encrypt(&noise, plaintext, json_len + 1,
                                    ciphertext, sizeof(ciphertext), &sealed_len);
    if (rc == THALOVANT_OK) { /* send all sealed_len bytes in order */ }
    else { /* close transport; no retry on this cipher state */ }
}
```

WSS sends this as a binary frame. MQTT publishes these bytes as its payload.
HTTP Base64-encodes the bytes in form fields `message=<base64>&binary=1` to
`POST /send_message`; use the same cookie session as `/connect`, check JSON
`error` fields even on HTTP 200, and poll `/get_binary_messages` for
`b64_messages`. Cleartext handshake envelopes use the normal text bindings.
Transport setup, authorization and MQTT topic helpers remain caller concerns.

Noise counters are implicit, ordered and separate per direction; AESGCM
encodes them big endian after four zero nonce bytes. Replays, reordering,
nonce exhaustion or malformed markers permanently invalidate the state.
Receive using `thalovant_noise_decrypt`, then inspect the authenticated first
byte: 0 JSON, 1 binary, 2 first JSON chunk, 3 first binary chunk, 4 middle,
5 final. Application send chunks are at most 65000 bytes excluding the marker.
Core validates sequence, while your application must bound total reassembly,
track whether the first chunk was JSON/binary and discard partial buffers on
failure/disconnect. Use a 32 MiB maximum or a lower device-specific budget.
Never interleave chunks from different application messages.

## Independent validation

`tests/fixtures/noise-node.json` contains synthetic keys and complete Node SDK
XX/KK transcripts, including both-direction ciphertext at counters 0–2.
`tools/generate-noise-vectors.mjs /path/to/built/thalovant-node-sdk` regenerates
it from the independently implemented Node engine with only its ephemeral RNG
replaced by fixed test bytes. `tools/noise-fixture-header.py` renders the C
fixture constants. Both GCC and Clang tests remain network-free. Swift uses
the same first-party C sources and separately verifies the JSON WSS binding.
